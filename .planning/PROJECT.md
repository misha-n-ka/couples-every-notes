# Couples Dashboard

## What This Is

Личное веб-приложение для пары: на первом этапе для пользователя и его жены. Оно объединяет желания, идеи и события в общем пространстве пары и личном пространстве каждого участника.

Первая версия работает в браузере на телефоне и компьютере. В ней два заранее созданных аккаунта с отдельным входом по логину и паролю; подключение других пар запланировано на будущее.

## Core Value

Помогать паре хранить желания и совместные планы в одном месте, сохраняя личные идеи для сюрпризов приватными.

### Out of Scope

В MVP не входят; сроки и порядок дальнейшей разработки не определены:

- Пользовательские шаблоны заметок, включая категорию и цвет карточки.
- Фото и изображения в заметках.
- Задачи со статусами и исполнителями.
- Открытая регистрация, подключение других пар и их отдельных пространств.
- Расширение авторизации для новых пользователей и фактическая миграция на выбранный позднее механизм входа. Сохранение существующих данных при этом — требование к MVP.
- Отдельные приложения для других платформ.

## Context

### Учебная цель

Помимо полезного приложения для пары, проект служит полигоном для изучения TypeScript и React с нуля. Пользователь выбрал Next.js, поскольку хочет освоить эти технологии на реальном продукте. При разработке нужны небольшие понятные изменения и краткие объяснения ключевых решений на примерах из проекта.

### Пространства и видимость

| Вид заметки | Кто видит | Кто редактирует и удаляет | Пример |
|------------|-----------|--------------------------|--------|
| Общая | Оба участника | Оба участника | Что посмотреть вместе |
| Личная, доступная партнёру | Автор и партнёр | Автор | Желаемые подарки |
| Приватная | Только автор | Автор | Идеи сюрпризов |

«Публичный» список означает доступность партнёру внутри пары. Интернет-публикация и доступ посторонних в MVP не предусмотрены. Правила видимости распространяются и на события.

При сохранении общей заметки в личное пространство создаётся отдельная личная копия. Исходная запись остаётся общей с прежними правами; изменения копии и исходника независимы. Решение уточнено пользователем при обсуждении дизайна 2026-11-09; детали UX фиксируются в [design.md](../design.md).

### Заметки и события

- Темы заметок: подарки, еда, хобби, фильмы и сериалы. Обязательная привязка каждой темы к конкретному пространству не задавалась.
- Заметка содержит название, описание и необязательную ссылку. Фото и изображения отложены.
- Событие или мероприятие — та же заметка с датой и, при необходимости, временем.
- Событие на весь день содержит дату без времени.
- Если время указано, обязательны начало и окончание события.
- Начало и окончание имеют собственные даты; события через полночь поддерживаются.
- У события со временем выбирается часовой пояс, по умолчанию Москва (`Europe/Moscow`).
- Личная копия общего события сохраняет расписание, часовой пояс и признак «Весь день»; исходник остаётся общим.
- Раздел «События» — месячная календарная сетка. Собственные приватные события видны в «Моём» и «Событиях», а на «Главной» скрыты. Приватные события партнёра недоступны.
- Экспорт создаёт файл одного события в формате iCalendar (`.ics`) с данными заметки и выбранным расписанием. Это разовая копия события.
- Google Календарь поддерживает импорт `.ics` на компьютере. Системный шаринг зависит от возможностей браузера; скачивание файла остаётся доступным способом экспорта.

### Сохранение данных при развитии авторизации

Обоим участникам и пространству нужны постоянные внутренние идентификаторы, независимые от логина или будущего способа входа. При переходе на расширенную авторизацию должна сохраняться связь новых данных входа с существующими участниками, их заметками, событиями, авторством и пространством пары.

Конкретный провайдер и механизм миграции пока не выбраны. Поддержка других пар позднее не должна требовать пересоздания текущего пространства.

### Будущие шаблоны

Пользователь создаёт шаблон «Десерт» в категории «Еда» и задаёт цвет карточки. Затем открывает шаблон и создаёт из него заметку «Торт медовый», получающую настройки шаблона. Другие параметры шаблона, правила доступа и поведение уже созданных заметок при изменении шаблона определим при разработке этой функции.

## Constraints

- **Объём MVP:** одна пара и два заранее созданных аккаунта; будущие улучшения не добавляются в первую версию автоматически.
- **Доступ:** приватные заметки доступны только автору; личные списки для партнёра и общие заметки имеют разные права изменения.
- **Данные:** заметки и события сохраняются между сеансами; развитие авторизации должно сохранять существующие данные и связи.
- **Хранение:** PostgreSQL для базы данных, Drizzle для работы с данными и миграций. Конкретные версии ещё не выбраны.
- **Приложение:** Next.js с React и TypeScript; вход и сессии — Better Auth. Стек согласован, конкретные версии ещё не выбраны.
- **Размещение:** управляемый облачный сервис; конкретный провайдер, тариф и конфигурация хранилища ещё не выбраны.
- **Рабочий процесс:** действуют правила корневого `AGENTS.md`, включая ограничения на сборку, staging, коммиты и отправку изменений.
- **Секреты:** данные входа и другие секреты не включаются в проектные документы и отслеживаемые файлы.

## Key Decisions

| Решение | Причина | Состояние |
|---------|---------|-----------|
| Начать с браузерного приложения | Выбранная пользователем первая платформа | Согласовано |
| Два заранее созданных аккаунта и одно пространство пары | Первый запуск для пользователя и его жены | Согласовано |
| Общее и личное пространства с тремя режимами доступа | Совместные планы, пожелания партнёру и приватные сюрпризы | Согласовано |
| Начать с заметок; задачи и изображения отложить | Ограничение объёма первой версии | Согласовано |
| События на весь день или с началом и окончанием | Дополнение MVP для мероприятий | Согласовано |
| Экспорт отдельного события в `.ics` | Перенос события в Google Календарь через файл | Согласовано |
| Сохранять идентичность участников и пространства при смене авторизации | Будущее развитие без потери накопленных данных | Согласовано |
| Шаблоны заметок отложить | Зафиксировать направление развития без расширения MVP | Согласовано |
| Агенты используют активную модель сессии (`inherit`) | Выбор пользователя для процесса разработки | Настроено в GSD |
| Использовать CLI `ast-index` для индекса и графовой навигации по коду | Выбор пользователя для исследования исходников и связей | Правила в AGENTS.md; первоначальный индекс создан |
| Использовать управляемый облачный сервис для размещения | Выбор пользователя после сравнения с VPS | Согласовано; провайдер и тариф открыты |
| PostgreSQL + Drizzle | Пользователь подтвердил выбор после обсуждения альтернатив | Согласовано; зависимости ещё не устанавливались |
| TypeScript + Better Auth | Пользователь подтвердил язык и библиотеку входа и сессий | Согласовано |
| Next.js + React | Пользователь выбрал Next.js после сравнения альтернатив; проект также нужен для изучения TypeScript и React | Согласовано |
