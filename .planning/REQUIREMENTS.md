# Requirements: Couples Dashboard

**Defined:** 2026-11-07
**Core Value:** Хранить желания и совместные планы пары в одном месте, сохраняя приватность личных идей.
**Scope:** Состав MVP и список будущих улучшений согласованы пользователем. Ни одно требование пока не реализовано и не проверено.

## v1 Requirements

### Браузерное приложение

- [ ] **WEB-01**: Оба участника могут пользоваться приложением в браузере на телефоне и компьютере; интерфейс адаптируется к размеру экрана.

### Аккаунты и пространства

- [ ] **ACC-01**: Каждый из двух участников входит под своим заранее созданным аккаунтом с логином и паролем; открытая регистрация в MVP отсутствует.
- [ ] **ACC-02**: После входа оба участника имеют доступ к одному общему пространству своей пары.
- [ ] **ACC-03**: Каждый участник имеет личное пространство со своими заметками, включая доступные партнёру и приватные.

### Заметки

- [ ] **NOTE-01**: Участник может создать заметку с названием, описанием и необязательной ссылкой.
- [ ] **NOTE-02**: Участник может просматривать сохранённые заметки, к которым имеет доступ.
- [ ] **NOTE-03**: Участник может изменить заметку, на изменение которой у него есть права.
- [ ] **NOTE-04**: Участник может удалить заметку, на удаление которой у него есть права.
- [ ] **NOTE-05**: Заметки можно относить к темам «Подарки», «Еда», «Хобби», «Фильмы и сериалы».
- [ ] **NOTE-06**: Изменения заметок сохраняются после обновления страницы и повторного входа; доступные обоим участникам данные доступны каждому при входе под своим аккаунтом.

### Видимость и права

- [ ] **VIS-01**: Общие заметки доступны обоим участникам для просмотра, редактирования и удаления.
- [ ] **VIS-02**: Личную заметку, доступную партнёру, читают оба участника; изменяет и удаляет её только автор. Так можно вести список желаемых подарков.
- [ ] **VIS-03**: Приватную заметку просматривает, изменяет и удаляет только автор. Партнёр не получает её содержимое ни в списках, ни при прямом обращении к записи. Так можно хранить идеи сюрпризов.
- [ ] **VIS-04**: Правила видимости и изменения заметок действуют также для событий и мероприятий.

### События и мероприятия

- [ ] **EVT-01**: Участник может добавить к заметке расписание события или мероприятия, сохранив её название, описание, ссылку и режим доступа.
- [ ] **EVT-02**: Для события на весь день участник указывает дату; время начала и окончания отсутствует.
- [ ] **EVT-03**: Если событие имеет время, участник обязан указать и начало, и окончание.
- [ ] **EVT-04**: Приложение не сохраняет событие со временем, если начало или окончание отсутствует либо окончание не позже начала. Формат ввода дат и часовой пояс уточняются при проектировании.

### Экспорт в календарь

- [ ] **CAL-01**: Участник может скачать отдельное доступное ему событие как файл iCalendar с расширением `.ics`.
- [ ] **CAL-02**: Экспорт сохраняет название, описание, ссылку и расписание события: дату для события на весь день либо начало и окончание для события со временем, с корректной интерпретацией часового пояса.
- [ ] **CAL-03**: Экспортированный файл можно импортировать в Google Календарь на компьютере с сохранением данных и расписания события. Экспорт представляет разовую копию.
- [ ] **CAL-04**: Если браузер поддерживает системную передачу этого файла, участник может воспользоваться действием «Поделиться»; при отсутствии поддержки доступно скачивание `.ics`.

### Совместимость с будущей авторизацией

- [ ] **MIG-01**: Участники и пространство пары имеют постоянные внутренние идентификаторы; авторство заметок и событий, принадлежность пространству и права доступа не зависят от логина или будущего способа входа.
- [ ] **MIG-02**: Модель данных позволяет связать будущие полноценные аккаунты с обоими существующими участниками и сохранить пространство пары, заметки, события, авторство и права доступа. Выполнение самой миграции относится к будущему расширению авторизации.

## v2 Requirements

Дальнейшее развитие, за пределами MVP. Название раздела не задаёт сроки, порядок или обязательный состав следующего релиза.

### Шаблоны заметок

- **TPL-01**: Пользователь может создать именованный шаблон заметки и указать его категорию.
- **TPL-02**: В шаблоне можно задать цвет карточки; состав других параметров будет определён отдельно.
- **TPL-03**: Пользователь может открыть шаблон и создать из него новую заметку, получающую настройки шаблона.

Пример: шаблон «Десерт» в категории «Еда» с выбранным цветом → новая заметка «Торт медовый». Доступность шаблонов партнёру и изменение ранее созданных заметок при обновлении шаблона пока не определены.

### Другие улучшения

- **MEDIA-01**: Фото и изображения в заметках.
- **TASK-01**: Задачи со статусами.
- **TASK-02**: Назначение исполнителя задачи.
- **AUTH-01**: Расширение авторизации и подключение новых пользователей с переносом обоих текущих участников на полноценные аккаунты без потери данных по MIG-01 и MIG-02.
- **PAIR-01**: Поддержка других пар с отдельными пространствами и изоляцией их данных; сохранение текущего пространства при расширении приложения.
- **PLAT-01**: Возможность выпуска приложений для других платформ; конкретные платформы пока не выбраны.

## Out of Scope

| Возможность | Причина исключения из MVP |
|------------|--------------------------|
| Пользовательские шаблоны и их настройки | Явно отложены пользователем |
| Фото и изображения | Текста и ссылки достаточно для первой версии |
| Задачи, статусы и исполнители | Первый этап ограничен заметками и событиями |
| Открытая регистрация и другие пары | Первая версия предназначена для двух участников |
| Расширенная авторизация и фактическая миграция | Реализуются позднее; совместимость данных предусмотрена уже в MVP |
| Приложения для других платформ | Первая платформа — браузер |

## Definition of Done

Для завершения MVP необходимо реализовать и проверить все требования v1. Для проверок доступа используются оба аккаунта; для календаря отдельно проверяются событие на весь день и событие со временем. Будущие требования не включаются в эту проверку.

Проверки, требующие сборки или компиляции, выполняются только после явного разрешения пользователя согласно `AGENTS.md`. Невыполненные проверки указываются явно; фиксация документов не подтверждает работоспособность приложения.
